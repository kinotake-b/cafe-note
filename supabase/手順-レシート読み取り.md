# レシートの写真読み取りを使えるようにする手順(最初の1回だけ)

仕組み: アプリ → Supabase の中継(Edge Function `read-receipt`)→ Gemini → 結果がアプリに戻る。
Gemini のキーは Supabase の中にだけ置く(アプリに入れると、公開ページなので誰でも盗める)。
中継は、`ALLOWED_EMAILS` に書いた人(自分)がログインしているときだけ動く。レシピ帳とカフェ帳で、同じ中継を使う。

## 1. Gemini のキーを作る(自分で)
1. https://aistudio.google.com を開き、Google アカウントでログインする。
2. 「Get API key」からキーを作る。
3. **課金(Billing)を有効にして、有料の枠にする。** 無料の枠だと、送った写真が Google の製品の改善に使われうる(公式の料金ページにそう書いてある)。レシートには店名やカードの末尾が写るので、有料の枠が安全。
4. 使いすぎを防ぐため、Google Cloud 側で予算アラート(例: 月500円)を設定しておく。
5. キーは他人に見せない。チャットや公開ページに貼らない。

## 2. 中継を置く(Supabase の画面で)
1. Supabase のプロジェクトを開き、左メニューの **Edge Functions** → **Deploy a new function** → **Via Editor**。
2. 関数の名前は **`read-receipt`**(この名前のとおりに)。
3. 中身は、`recipe-app/supabase/functions/read-receipt/index.ts` の全文をコピーして貼り付け、**Deploy**。
4. 関数の設定画面で、**Verify JWT をオフ**にする(関数の中で、ログイン中の本人かを自分で確かめているため)。

## 3. 秘密の値(Secrets)を入れる
**Edge Functions → Secrets** で、次を追加する。

| 名前 | 値 |
|---|---|
| `GEMINI_API_KEY` | 1 で作ったキー |
| `ALLOWED_EMAILS` | 自分のメールアドレス(同期でログインしているもの。複数ならカンマ区切り) |
| `GEMINI_MODEL` | (省略可)モデル名。省略すると `gemini-3.5-flash-lite`。モデルが古くなって動かなくなったら、ここだけ変える |

## 4. 勝手に登録されないようにする(おすすめ)
自分のアカウントを作り終えたら、**Authentication → Sign In / Providers** の **User Signups** で、**Allow new users to sign up** をオフにする。
(アプリのページは公開されているので、このままだと、知らない人がアカウントを作れてしまう。`ALLOWED_EMAILS` で中継は守られているが、念のため。)

## 5. 使い方
- レシピ帳: マイページの値段帳 →「レシートから登録」→「写真から読み取る」。
- カフェ帳: 記録の編集画面の「レシートの写真から入力」。
- 読み取り結果は、必ず確認してから保存する(読み違いは起こりうる)。合計が合わないときは、赤い警告が出る。
